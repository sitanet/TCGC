════════════════════════════════════════════════════════════════════════════════


                        FIELD DESCRIPTIONS
                        ═════════════════


┌─ TO (RECIPIENT)
│  ├─ Icon: Gold circle with church icon
│  ├─ Value: "CityGate Church" (from wallet provider)
│  ├─ Purpose: Shows who receives the money
│  └─ Example: "The CityGate Church"

├─ PURPOSE (TRANSACTION TYPE)
│  ├─ Value: "Tithe", "Giving", "Send Money", etc.
│  ├─ Purpose: Shows type of transaction
│  └─ Example: "Tithe"

├─ ACCOUNT NO. (OPTIONAL)
│  ├─ Value: Church's bank account number
│  ├─ Purpose: Confirmation of bank account
│  ├─ Example: "1234567890"
│  └─ Note: Only shown if available in wallet provider
│           ⚠️ USER CONCERN: May need to be hidden (privacy)

├─ ACCOUNT NAME (OPTIONAL)
│  ├─ Value: Church account name
│  ├─ Purpose: Identifies the account
│  ├─ Example: "Church Operations Account"
│  └─ Note: Only shown if available in wallet provider

├─ AMOUNT
│  ├─ Value: User-entered amount
│  ├─ Format: ₦10,000.00
│  ├─ Purpose: Shows base transaction amount
│  └─ Weight: Medium-bold

├─ FEE
│  ├─ Value: Service/transaction fee calculated by system
│  ├─ Format: ₦50.00
│  ├─ Purpose: Shows processing fee
│  └─ Note: Calculated based on amount and transaction type

├─ VAT
│  ├─ Value: Value Added Tax (if applicable)
│  ├─ Format: ₦10.00
│  ├─ Purpose: Shows tax component
│  ├─ Note: Only shown if VAT > 0
│  └─ Calculation: Often based on fee

└─ TOTAL (IMPORTANT)
   ├─ Value: Amount + Fee + VAT
   ├─ Format: ₦10,060.00
   ├─ Style: BOLD, GOLD COLOR, Larger font
   ├─ Purpose: Total amount user will pay
   └─ Note: This is what actually gets deducted from wallet


════════════════════════════════════════════════════════════════════════════════


                        BALANCE CARD DETAILS
                        ══════════════════


FORMAT:
    Wallet Balance
    ₦50,000 → ₦39,940 after  ✓

COMPONENTS:
    ├─ Label: "Wallet Balance"
    ├─ Current balance: ₦50,000
    ├─ Arrow: →
    ├─ Balance after transaction: ₦39,940
    └─ Success icon: ✓ (Green checkmark)

CALCULATION:
    Balance After = Current Balance - Total Amount
    ₦50,000 - ₦10,060 = ₦39,940

COLORS:
    ├─ Border: Green (success green)
    ├─ Text: Default (white in dark, black in light)
    └─ Icon: Green checkmark

PURPOSE:
    Shows user their current balance and confirms they have enough funds

CLOSE BUTTON (X):
    ├─ Location: Top right of sheet
    ├─ Action: Closes this sheet
    ├─ Returns to: Amount entry screen
    └─ Note: No transaction is processed

PAY BUTTON:
    ├─ Location: Bottom of sheet
    ├─ Label: "Pay"
    ├─ Color: Gold background, white text
    ├─ Action: 
    │   1. Closes confirmation sheet
    │   2. Opens PIN entry sheet
    │   3. User enters 4-digit PIN
    ├─ Enabled when: Always (if balance sufficient)
    └─ Next: PIN verification sheet


════════════════════════════════════════════════════════════════════════════════


                        EDGE CASES
                        ═════════


CASE 1: NO ACCOUNT NUMBER
    If churchAccountNumber is null:
    ├─ Account No. row: NOT SHOWN
    └─ Sheet shows only: To, Purpose, Amount, Fee, VAT, Total


CASE 2: NO ACCOUNT NAME
    If churchAccountName is null:
    ├─ Account Name row: NOT SHOWN
    └─ Sheet shows only: To, Purpose, Account No., Amount, Fee, VAT, Total


CASE 3: NO VAT
    If VAT == 0:
    ├─ VAT row: NOT SHOWN
    └─ Shows only: Amount and Fee


CASE 4: INSUFFICIENT BALANCE
    If balance < total:
    ├─ Balance card: Shows red or warning color
    ├─ Pay button: DISABLED or shows warning
    └─ Message: "Insufficient balance" (if implemented)


CASE 5: HIGH AMOUNT
    If amount is very large:
    ├─ Font size: Adjusts responsively
    ├─ Line breaks: Text wraps properly
    └─ Layout: Remains readable

════════════════════════════════════════════════════════════════════════════════


                    WHAT HAPPENS WHEN USER TAPS "PAY"
                    ════════════════════════════════


SEQUENCE:
    1. User reviews all details on confirmation sheet
    2. User sees adequate balance (green checkmark)
    3. User taps "Pay" button
    4. This sheet closes (Navigator.pop)
    5. PIN Entry Sheet opens
    6. User enters 4-digit PIN
    7. PIN is validated
    8. If PIN correct → Transaction processing begins
    9. If PIN wrong → Error message, can retry
    10. After processing → Success or Failure page
