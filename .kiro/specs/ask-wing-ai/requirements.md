# Ask Wing AI - Requirements Document

## Introduction

Ask Wing AI is an AI-powered question-answering system integrated into the TCGC mobile app. It enables users to ask questions about all sermons and audio content uploaded to the server, with responses that include accurate citations, speaker references, and timestamps. The feature provides a conversational interface through a floating action button on the home page, leveraging OpenAI's GPT-4 model and vector embeddings for semantic search across sermon transcripts.

This feature bridges the gap between users and the vast library of sermon content, making it easier for users to find relevant teachings without manually searching through hours of audio.

## Glossary

- **Floating Action Button (FAB)**: A prominent circular button displayed on the home page that opens the Ask Wing AI chat interface
- **Ask Wing AI**: The AI-powered Q&A system that searches sermon transcripts and provides answers with citations
- **Sermon Transcript**: The text transcription of an audio sermon stored in the database
- **Embedding**: A vector representation of text generated by OpenAI's embedding model for semantic search
- **Citation**: A reference to the source of information, including sermon title, speaker name, and timestamp
- **Timestamp**: The specific time within an audio sermon where relevant content is located (e.g., "24:35" for 24 minutes 35 seconds)
- **Vector Search**: Semantic search technique using embeddings to find conceptually similar content
- **Chat History**: The record of questions and answers within a single user session
- **RAG (Retrieval Augmented Generation)**: Technique combining document retrieval with language model generation
- **Rate Limiting**: A mechanism to control how many requests a user can make within a specific time period
- **GPT-4**: OpenAI's advanced language model used for generating responses
- **OpenAI Embeddings**: Vector representations generated by OpenAI's embedding model for semantic search
- **Authentication Token**: Security credential that verifies a user's identity before accessing Ask Wing AI
- **Moderation**: Process of reviewing user questions for compliance with community guidelines
- **Speaker**: The person delivering the sermon or audio content
- **Message**: A sermon or audio content piece in the system
- **User**: An authenticated TCGC app user who can access the Ask Wing AI feature

## Requirements

### Requirement 1: Display Floating Action Button on Home Page

**User Story:** As a user, I want to see a floating action button on the home page, so that I can quickly access the Ask Wing AI feature.

**Acceptance Criteria**

1. THE Home_Page SHALL display an Ask Wing AI floating action button in the bottom-right corner
2. WHERE the device is in portrait orientation, THE Floating_Action_Button SHALL remain visible and positioned in the bottom-right corner with appropriate padding
3. WHERE the device is in landscape orientation, THE Floating_Action_Button SHALL remain visible and repositioned with appropriate padding
4. THE Floating_Action_Button SHALL display the text "Ask Wing AI" or an appropriate icon
5. WHEN the user taps the floating action button, THE Chat_Interface SHALL open in a modal or full-screen view
6. THE Floating_Action_Button SHALL remain visible while the user is viewing the home page

---

### Requirement 2: Authenticate User Before Accessing Ask Wing AI

**User Story:** As an app administrator, I want to ensure only authenticated users can access Ask Wing AI, so that I can maintain security and control access to the feature.

**Acceptance Criteria**

1. WHEN the user is not authenticated, THE Chat_Interface SHALL not open
2. WHEN the user is not authenticated and taps the floating action button, THE System SHALL redirect the user to the login page
3. WHEN the user completes authentication and returns to the home page, THE Floating_Action_Button SHALL be enabled
4. WHEN the user's authentication token expires during an Ask Wing AI session, THE System SHALL display an error message and prompt the user to re-authenticate
5. THE Authentication_Service SHALL verify the user's token validity before allowing access to Ask Wing AI
6. WHERE the user is authenticated, THE Chat_Interface SHALL be accessible

---

### Requirement 3: Open Conversational Chat Interface

**User Story:** As a user, I want to see a clean chat interface when I tap the Ask Wing AI button, so that I can ask questions about sermons.

**Acceptance Criteria**

1. WHEN the user taps the floating action button, THE Chat_Interface SHALL open displaying a message list area and input field
2. THE Chat_Interface SHALL display a header with "Ask Wing AI" title
3. THE Chat_Interface SHALL include an input field at the bottom where users can type their questions
4. WHERE the chat history is empty, THE Message_List_Area SHALL display a welcome message or prompt
5. THE Chat_Interface SHALL include a close button to dismiss the interface
6. WHEN the chat interface is open, THE Floating_Action_Button SHALL remain visible for easy reference
7. THE Chat_Interface SHALL support scrolling through the message list if content exceeds the visible area

---

### Requirement 4: Submit Questions Through Chat Interface

**User Story:** As a user, I want to type and send questions to Ask Wing AI, so that I can get answers about sermon content.

**Acceptance Criteria**

1. WHEN the user enters text in the input field, THE Input_Field SHALL accept and display the text
2. WHEN the user taps the send button, THE User_Message SHALL be added to the message list
3. WHEN the user submits a question, THE Input_Field SHALL be cleared for the next question
4. IF the user submits an empty message, THEN THE Chat_Interface SHALL display an error or disable the send button
5. WHEN the user taps the send button, THE Backend_Service SHALL receive the question with the user's authentication context
6. THE Chat_Interface SHALL display user messages in a visually distinct format (e.g., aligned to the right or different color)
7. WHILE the AI is processing the question, THE Chat_Interface SHALL display a loading indicator

---

### Requirement 5: Search Sermon Transcripts Using Vector Embeddings

**User Story:** As the system, I want to find relevant sermons based on user questions, so that Ask Wing AI can provide accurate answers grounded in sermon content.

**Acceptance Criteria**

1. WHEN the user submits a question, THE Embedding_Service SHALL generate a vector embedding of the question using OpenAI's embedding model
2. WHEN a vector embedding is generated, THE Vector_Search SHALL retrieve the top N most semantically similar sermon transcripts from the database
3. THE Vector_Search SHALL return sermon documents with metadata including sermon title, speaker name, and timestamp information
4. WHERE multiple sermons are relevant to the question, THE Search_Service SHALL return the top 5 most relevant sermons ordered by semantic similarity
5. IF no sermons meet a minimum relevance threshold, THEN THE System SHALL still attempt to provide an answer based on available context
6. THE Embedding_Service SHALL use OpenAI's text-embedding-3-small model or equivalent for consistency and performance

---

### Requirement 6: Generate AI Responses with Citations

**User Story:** As a user, I want Ask Wing AI to answer my questions with clear references to specific sermons, so that I can verify the information and find the original content.

**Acceptance Criteria**

1. WHEN the AI generates a response, THE Response_Generator SHALL include citations referencing the sermon title and speaker name
2. WHEN a response references specific sermon content, THE Citation SHALL include the sermon title, speaker name, and the relevant timestamp
3. THE Citation_Format SHALL be consistent and readable (e.g., "- [Sermon Title] by [Speaker Name] at [timestamp]")
4. WHERE the question cannot be answered from sermon content, THE Response_Generator SHALL indicate that the information is not available in the sermon library
5. WHEN the AI generates a response, THE Response SHALL include only information sourced from the sermon transcripts or general knowledge appropriate to the context
6. THE Response_Generator SHALL use GPT-4 with a system prompt that enforces citation requirements and accuracy
7. WHERE the AI references multiple sermons, THE Response_Generator SHALL list all relevant citations in a dedicated section at the end of the response

---

### Requirement 7: Display Timestamps in Responses

**User Story:** As a user, I want to see timestamps in Ask Wing AI responses, so that I can jump directly to the relevant part of the sermon audio.

**Acceptance Criteria**

1. WHEN the AI references a specific part of a sermon, THE Response SHALL include the timestamp in the format "MM:SS" (e.g., "24:35")
2. WHEN a timestamp is displayed, THE Citation_Block SHALL show "at [timestamp]" following the sermon title and speaker name
3. WHERE the AI provides multiple timestamps within one response, THE Response SHALL list each timestamp clearly associated with its content
4. THE Timestamp_Accuracy SHALL be verified against the sermon metadata; only timestamps within the sermon duration SHALL be included
5. IF a timestamp is not available or cannot be determined, THEN THE Response_Generator SHALL omit the timestamp but include the sermon title and speaker
6. WHERE a user taps on a timestamp in the response, THE System SHALL attempt to navigate to the sermon player with the audio position set to the timestamp (future enhancement)

---

### Requirement 8: Format Responses with Markdown Support

**User Story:** As a user, I want Ask Wing AI responses to be well-formatted and easy to read, so that I can quickly understand the answer.

**Acceptance Criteria**

1. THE Response_Formatter SHALL support markdown formatting including bold, italics, bullet points, and numbered lists
2. WHEN the AI generates a response, THE Response_Display SHALL render markdown formatted text correctly
3. THE Response_Display SHALL use appropriate text styling (e.g., larger font for headings, different color for citations)
4. WHERE the response contains multiple sections, THE Response_Formatter SHALL use markdown headers to clearly separate them
5. THE Citation_Block SHALL be formatted as a clearly separated section at the end of the response using markdown styling
6. WHEN displaying links or references, THE Response_Display SHALL format them as clickable elements where appropriate

---

### Requirement 9: Persist Chat History During Session

**User Story:** As a user, I want my conversation history to remain available while Ask Wing AI is open, so that I can refer back to previous questions and answers.

**Acceptance Criteria**

1. WHEN the user asks a question and receives an answer, THE Chat_History SHALL store both the question and the AI response
2. WHEN the user scrolls up in the message list, THE Previous_Messages SHALL be visible and readable
3. WHILE the chat interface is open, THE Chat_History SHALL persist in memory
4. WHERE the user closes and reopens the chat interface, THE Chat_History SHALL be cleared (session-based only)
5. THE Chat_History SHALL display the most recent message at the bottom of the message list
6. WHEN new messages are added, THE Message_List_Area SHALL automatically scroll to show the latest message

---

### Requirement 10: Store Questions for Moderation and Analytics

**User Story:** As an administrator, I want to log user questions for moderation and analytics, so that I can ensure appropriate content and improve the service.

**Acceptance Criteria**

1. WHEN the user submits a question, THE Moderation_Logger SHALL store the question with a timestamp and the user ID
2. THE Moderation_Logger SHALL store questions in a secure database accessible only to administrators
3. WHERE personal data is included in a question, THE System SHALL strip or anonymize it before storing
4. THE Stored_Question_Record SHALL include the question text, user ID, timestamp, and response summary
5. IF a question contains potential policy violations, THEN THE Moderation_Alert SHALL flag it for review by administrators
6. THE Moderation_Logger SHALL not store the complete AI response, only a summary or metadata

---

### Requirement 11: Implement Rate Limiting to Prevent Abuse

**User Story:** As an app administrator, I want to limit the number of questions a user can ask, so that I can prevent abuse and control API costs.

**Acceptance Criteria**

1. WHEN a user submits a question, THE Rate_Limiter SHALL check if the user has exceeded their question limit
2. WHERE a user has reached their daily question limit, THE System SHALL display an error message indicating they must wait until the next day
3. THE Rate_Limiter SHALL enforce a limit of N questions per user per day (to be configured by administrators)
4. WHERE a user approaches their daily limit, THE Chat_Interface SHALL optionally display a remaining question count
5. IF a user exceeds the rate limit, THEN THE Chat_Interface SHALL prevent further submissions and show a helpful message
6. THE Rate_Limiter SHALL track question counts per user ID using a backend service
7. WHEN the daily reset time occurs, THE Rate_Limiter SHALL reset all user question counts

---

### Requirement 12: Handle API Errors and Provide Fallback Responses

**User Story:** As a user, I want Ask Wing AI to gracefully handle errors, so that I receive helpful feedback when something goes wrong.

**Acceptance Criteria**

1. WHEN the OpenAI API is unavailable, THE Error_Handler SHALL display a user-friendly error message
2. WHEN the vector search fails, THE Error_Handler SHALL log the error and display a message indicating the service is temporarily unavailable
3. IF the embedding generation fails, THEN THE System SHALL display an error message and suggest the user try again later
4. WHEN an unexpected error occurs, THE Error_Handler SHALL display a generic error message without exposing technical details
5. WHERE an error occurs, THE Error_Message SHALL include a suggestion to try again or contact support
6. THE Error_Logging_Service SHALL log all errors with full technical details for administrators to review
7. WHEN the API rate limit is reached (OpenAI), THE System SHALL display a message indicating temporary unavailability

---

### Requirement 13: Secure API Keys and Credentials

**User Story:** As a security administrator, I want API keys and sensitive credentials to be stored securely, so that I can prevent unauthorized access to OpenAI and other services.

**Acceptance Criteria**

1. THE Backend_Service SHALL store the OpenAI API key in environment variables, never in source code or configuration files
2. WHERE the API key is used, THE Backend_Service SHALL use HTTPS/TLS encryption for all communication with OpenAI
3. THE Backend_Service SHALL implement request signing or other mechanisms to prevent credential exposure in logs
4. IF credentials are accidentally logged, THEN THE Logging_System SHALL mask or redact sensitive values
5. THE Backend_Database_Credentials SHALL be stored securely in environment variables accessible only to the backend service
6. WHEN the backend service receives a request, THE Request_Validator SHALL verify the request originates from an authenticated user
7. THE API_Key_Rotation SHALL be implemented to allow periodic key updates without downtime

---

### Requirement 14: Prevent Personal Data from Being Sent to OpenAI

**User Story:** As a privacy administrator, I want to ensure user personal data is not sent to external services, so that I can protect user privacy.

**Acceptance Criteria**

1. WHEN a user submits a question containing personal information, THE Data_Sanitizer SHALL remove or anonymize personally identifiable information before sending to OpenAI
2. THE Personal_Data_Types SHALL include names, email addresses, phone numbers, account numbers, and other sensitive identifiers
3. WHERE a question contains personal data, THE System SHALL store the sanitized version and keep the original only in local logs
4. WHEN the AI response is generated, THE Backend_Service SHALL use only the sanitized question
5. IF a question cannot be sanitized while maintaining meaning, THEN THE System SHALL flag it and either refuse to process or ask the user to rephrase
6. THE Data_Sanitization_Process SHALL be tested regularly to ensure personal data is not inadvertently transmitted
7. WHEN chat history is stored, THE Stored_Messages SHALL contain only sanitized question text and the AI response

---

### Requirement 15: Display Response Loading State

**User Story:** As a user, I want to see that Ask Wing AI is working on my question, so that I understand the system is processing and can see progress.

**Acceptance Criteria**

1. WHEN the user submits a question, THE Chat_Interface SHALL immediately display a loading indicator or typing animation
2. WHILE the backend service is processing the question, THE Loading_Indicator SHALL remain visible
3. THE Loading_Indicator SHALL be positioned near the bottom of the message list for visibility
4. WHERE the response takes longer than 10 seconds, THE Chat_Interface SHALL display an estimated wait time or cancel option
5. WHEN the AI response is ready, THE Loading_Indicator SHALL be replaced with the actual response
6. IF the response takes too long (e.g., > 30 seconds), THEN THE System SHALL display a timeout message and suggest retrying

---

### Requirement 16: Ensure Response Load Time Performance

**User Story:** As a user, I want Ask Wing AI to respond quickly to my questions, so that I don't have to wait too long for answers.

**Acceptance Criteria**

1. WHEN a user submits a question, THE System SHALL begin processing within 1 second
2. WHEN the AI is generating a response, THE Response_Should_Load within 10 seconds under normal conditions
3. THE Vector_Search_Performance SHALL return results within 2 seconds for typical queries
4. WHERE the embedding generation takes longer than 3 seconds, THE System SHALL consider implementing caching or optimization
5. IF response time exceeds 10 seconds, THEN THE User SHALL receive a notification explaining potential causes
6. THE Backend_Performance_Metrics SHALL be monitored and logged for continuous optimization
7. WHEN the system detects consistently slow response times, THE Administrators_SHALL be alerted to investigate

---

### Requirement 17: Support Conversational Context in Multiple Messages

**User Story:** As a user, I want to ask follow-up questions that reference previous answers, so that I can have a natural conversation with Ask Wing AI.

**Acceptance Criteria**

1. WHEN a user asks a follow-up question, THE System SHALL include the previous question and answer in the context sent to GPT-4
2. WHEN the AI generates a response to a follow-up question, THE Response_Generator SHALL reference previous context when relevant
3. WHERE the conversation has multiple turns, THE Context_Manager SHALL maintain awareness of the entire conversation thread
4. WHEN conversation context exceeds a maximum length, THE Context_Manager SHALL summarize older messages while preserving key information
5. THE Chat_History_Display SHALL show the complete conversation in order from oldest to newest message
6. WHERE the user asks about "it" or "that," THE AI_Context_Engine SHALL resolve pronouns to previous questions or answers

---

### Requirement 18: Backend API - Question Submission Endpoint

**User Story:** As a frontend developer, I want a backend API endpoint to submit user questions, so that I can integrate Ask Wing AI into the Flutter app.

**Acceptance Criteria**

1. THE Backend_API SHALL expose a POST endpoint at `/api/ask-wing-ai/questions` (or equivalent)
2. WHEN a request is sent to this endpoint, THE Backend_Service SHALL accept a JSON payload containing the user question
3. THE Question_Submission_Endpoint SHALL require authentication via a valid JWT token or session
4. WHERE the authentication token is invalid or expired, THE Endpoint SHALL return a 401 Unauthorized response
5. WHEN a valid question is received, THE Endpoint SHALL return a 200 OK response with a question ID
6. THE Request_Payload SHALL include the question text and optionally previous message IDs for context
7. WHEN the response is generated, THE Endpoint SHALL return the AI response with citations and timestamps

---

### Requirement 19: Backend API - Chat History Retrieval Endpoint

**User Story:** As a frontend developer, I want to retrieve chat history for a user, so that I can display previous conversations.

**Acceptance Criteria**

1. THE Backend_API SHALL expose a GET endpoint at `/api/ask-wing-ai/history` (or equivalent)
2. WHEN a request is sent to this endpoint, THE Backend_Service SHALL return the current session's chat history
3. WHERE pagination is needed, THE Endpoint SHALL accept limit and offset parameters
4. THE History_Response SHALL return messages in chronological order with timestamps
5. WHERE a user has no chat history, THE Endpoint SHALL return an empty list or appropriate response
6. THE Endpoint SHALL require authentication and return only the authenticated user's history
7. WHEN the chat session ends, THE History_SHALL be cleared based on session timeout

---

### Requirement 20: Backend API - Sermon Transcript Indexing and Updates

**User Story:** As a system administrator, I want to automatically index new sermon transcripts for search, so that Ask Wing AI can include the latest content.

**Acceptance Criteria**

1. WHEN a new sermon is uploaded to the server, THE Indexing_Service SHALL automatically generate embeddings for the sermon transcript
2. THE Embedding_Service SHALL break long transcripts into chunks for efficient search
3. WHERE sermon metadata changes (title, speaker), THE Indexing_Service SHALL update the stored embeddings and metadata
4. THE Indexing_Process SHALL run asynchronously without blocking other system operations
5. IF embedding generation fails for a sermon, THEN THE Indexing_Service SHALL log the error and retry with exponential backoff
6. THE Indexed_Sermons SHALL be stored in a vector database optimized for semantic search (e.g., Pinecone, Weaviate, or PostgreSQL with pgvector)
7. WHEN an old sermon is deleted, THE Vector_Index SHALL be updated to remove its embeddings

---

### Requirement 21: Sermon Transcript Metadata Association

**User Story:** As the system, I want to maintain accurate associations between transcripts and sermon metadata, so that Ask Wing AI can provide correct citations.

**Acceptance Criteria**

1. WHEN sermon transcripts are indexed, THE System SHALL maintain references to sermon ID, title, speaker name, date, and duration
2. WHEN the AI searches for relevant content, THE Search_Results SHALL include complete metadata for each relevant sermon
3. THE Sermon_Metadata SHALL be stored in a relational database with foreign keys linking to transcript chunks
4. WHERE sermon metadata is updated, THE System SHALL update the metadata in the search index without re-embedding
5. IF a sermon is missing required metadata (e.g., speaker name), THEN THE System SHALL log a warning and include available metadata in responses
6. WHEN generating citations, THE Citation_Generator SHALL verify that metadata is accurate before including in the response

---

### Requirement 22: Backend Logging and Monitoring

**User Story:** As an operations team member, I want to monitor Ask Wing AI system performance and debug issues, so that I can maintain service quality.

**Acceptance Criteria**

1. THE Backend_Logging SHALL record all question submissions with user ID, timestamp, and question text
2. WHEN an API request is processed, THE System SHALL log request parameters, response status, and processing time
3. THE Logging_System SHALL record embedding generation times and search performance metrics
4. WHEN an error occurs, THE Error_Logging SHALL include stack traces and relevant context
5. THE Monitoring_Dashboard SHALL display real-time metrics including API response times, question volume, and error rates
6. WHERE system performance degrades, THE Monitoring_Alerts SHALL notify administrators
7. THE Logs SHALL be retained for at least 30 days and stored securely

---

### Requirement 23: Clear Chat History Option

**User Story:** As a user, I want to clear my chat history, so that I can start a fresh conversation.

**Acceptance Criteria**

1. THE Chat_Interface SHALL display a clear history button or option
2. WHEN the user taps the clear history button, THE System SHALL display a confirmation dialog
3. WHERE the user confirms the action, THE Chat_History SHALL be immediately cleared
4. WHEN chat history is cleared, THE Message_List_Area SHALL display the welcome message again
5. THE Clear_History_Action SHALL only affect the current session (not previous session records stored for moderation)
6. WHEN the user closes and reopens the chat interface, THE Chat_History SHALL remain cleared

---

### Requirement 24: Provide Help and Documentation Within Chat Interface

**User Story:** As a user, I want access to help information about Ask Wing AI, so that I can learn how to get the best results.

**Acceptance Criteria**

1. THE Chat_Interface SHALL include a help button or icon
2. WHEN the user taps the help button, THE System SHALL display tips for asking effective questions
3. THE Help_Content SHALL explain that Ask Wing AI searches sermon transcripts and provide example questions
4. WHERE a user asks a question the system cannot answer, THE Response_Generator SHALL suggest rephrasing or provide help tips
5. THE Help_Documentation SHALL be accessible without closing the chat interface
6. THE Help_Content SHALL be localized to match the app's language settings

---

### Requirement 25: Automatic Sermon Audio Transcription on Upload

**User Story:** As a system administrator, I want sermon audio to be automatically transcribed when uploaded, so that Ask Wing AI has text content to search across.

**Acceptance Criteria**

1. WHEN a sermon audio file is uploaded to the server, THE Transcription_Service SHALL automatically begin processing the audio
2. THE Transcription_Service SHALL use OpenAI's Whisper model (or equivalent) to convert speech to text
3. WHERE the audio file is longer than 25 MB, THE System SHALL split the audio into chunks before transcription
4. THE Transcription_Process SHALL run asynchronously without blocking other upload operations
5. WHEN transcription completes successfully, THE Transcript_SHALL be stored in the Message/Sermon record
6. IF transcription fails, THEN THE System SHALL log the error and retry with exponential backoff (up to 3 attempts)
7. WHERE transcription partially fails (some audio chunks processed), THE System SHALL store available transcript with a warning flag
8. WHEN a transcript is stored, THE System SHALL trigger the sermon indexing process to generate embeddings
9. THE Transcription_Service SHALL track processing status (pending, processing, completed, failed) for each sermon
10. WHEN an admin queries sermon upload status, THE System SHALL display transcription progress and completion status

---

## Summary of Key Features

**User-Facing Features:**
- Floating Action Button on home page for easy access
- Conversational chat interface with message history
- Quick response times (< 10 seconds)
- Citations with sermon titles, speakers, and timestamps
- Well-formatted, readable responses

**Backend Features:**
- Vector embedding search across all sermon transcripts
- GPT-4 integration for intelligent responses
- User authentication and authorization
- Rate limiting to prevent abuse
- Security for API keys and credentials
- Session-based chat history
- Question logging for moderation
- Comprehensive error handling

**Admin/Operational Features:**
- Automatic indexing of new sermons
- Monitoring and logging
- Configurable rate limits
- Moderation tools for reviewing user questions
