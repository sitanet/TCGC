1. Introduction & Onboarding

The onboarding process is designed to be simple, secure, and welcoming. It introduces new users to the app while ensuring existing members can quickly access their accounts. The process captures essential information while respecting user privacy and time.

1.1 Get Started Screen

The Get Started screen serves as the welcoming gateway to the TCGC mobile experience. It is the first impression users have of the application and sets the tone for their entire journey.

Features of the Get Started Screen

  • Church Branding: Displays the official TCGC logo and brand colors, creating immediate recognition and trust
  • Welcome Message: A warm, inviting message that reflects the church's values and hospitality
  • Sign In Button: For returning members who already have accounts
  • Sign Up Button: For new members creating their first account

Why This Matters

First impressions are crucial in app engagement. A clean, branded welcome screen establishes credibility and helps users understand they are entering an official church platform. The clear distinction between Sign In and Sign Up reduces confusion and streamlines the entry process.

Benefits

  • Immediate brand recognition builds trust
  • Simple two-option choice reduces decision fatigue
  • Professional design reflects the church's commitment to excellence
  • Welcoming tone encourages continued engagement

1.2 User Registration (Sign Up)

The registration process is designed to collect essential information while being quick and non-intrusive. It balances the need for user data with respect for user time and privacy.

Registration Form Fields:

FieldPurposeValidation
First NamePersonal identification and greetingRequired, letters only
Last NameComplete name for recordsRequired, letters only
Email AddressPrimary login credential and communicationValid email format, unique
PasswordAccount securityMinimum 8 characters, complexity rules
Confirm PasswordPrevents typo errorsMust match password

Registration Process Flow:

  1. Form Completion: User fills in all required fields with real-time validation feedback
  2. Submission: Data is securely transmitted to the server via encrypted connection
  3. Account Creation: User account is created in the database with a "pending" status
  4. Email Confirmation: An automated email is sent with a unique confirmation link
  5. Success Feedback: User sees a confirmation message instructing them to check their email

Email Confirmation System

How it works: Upon registration, the system generates a unique token that is embedded in a confirmation link. This link is sent to the user's email address and expires after 24 hours for security.

Why email confirmation:

  • Verifies that the user owns the email address
  • Prevents fake or spam registrations
  • Ensures important communications reach the user
  • Adds a layer of account security

Resend Option: If the email doesn't arrive (spam folder, typo, etc.), users can request a new confirmation email, which invalidates any previous tokens.

Benefits of This Registration Approach

  • Security: Email verification ensures account authenticity
  • Simplicity: Only essential fields are required initially
  • Flexibility: Additional profile details can be added later
  • Trust: Professional process builds confidence in the platform
  • Communication: Verified email enables important notifications

1.3 User Sign In

The sign-in process prioritizes both security and convenience. It offers multiple authentication methods to accommodate different user preferences and device capabilities.

Authentication Methods:

1. Email + Password (Primary)

The standard authentication method using the email address registered during sign-up and a secure password. This method works on all devices and platforms.

  • Email is case-insensitive for user convenience
  • Password is securely hashed and never stored in plain text
  • Failed attempts are rate-limited to prevent brute force attacks

2. Biometric Authentication (Optional)

After initial email/password login, users can enable biometric authentication for faster subsequent logins.

  • Fingerprint: Uses device fingerprint sensor for quick authentication
  • Face ID: Uses facial recognition on supported devices
  • Fallback: Password option always available if biometrics fail

Why Biometric Authentication?

Modern users expect convenience without compromising security. Biometric authentication provides:

  • Faster login (under 1 second vs. typing credentials)
  • Higher security (biometrics are harder to steal than passwords)
  • Better user experience (no need to remember passwords)
  • Reduced password fatigue

JWT Token Authentication System:

The app uses JSON Web Tokens (JWT) for secure session management:

Token TypeLifespanPurpose
Access TokenShort (minutes)Authenticates API requests
Refresh TokenLonger (days)Obtains new access tokens without re-login

Benefits of JWT Authentication

  • Stateless: Server doesn't need to store session data
  • Scalable: Works across multiple servers
  • Secure: Short-lived tokens limit exposure if compromised
  • Seamless: Automatic refresh keeps users logged in

Forgot Password Recovery:

A secure password recovery system allows users to regain access to their accounts:

  1. Request: User enters their registered email address
  2. Validation: System verifies email exists (without revealing this to prevent enumeration)
  3. Email: Reset link sent with unique, time-limited token (1 hour expiry)
  4. Reset: User sets new password via secure web form
  5. Confirmation: Old password invalidated, user can login with new credentials

7. Wallet & Giving System

The Wallet system is a comprehensive financial feature that enables members to give offerings, tithes, and donations directly from their mobile device. It integrates with 9 Payment Service Bank (9PSB) to provide real banking capabilities, making giving as convenient as mobile banking.

7.1 Wallet Overview

The wallet dashboard provides a complete view of the user's financial activity within the church:

Dashboard Elements

ElementDescription
Current BalanceAvailable funds in Naira (₦)

Account NameUser's registered name
Wallet TierCurrent verification level (0-3)
Quick ActionsButtons for common transactions

7.2 Wallet Setup Process

Setting up a wallet is a guided process that creates a real bank account for the user:

Step 1: Create Wallet

  • User initiates wallet creation from the app
  • System communicates with 9PSB API
  • Real bank account number is generated instantly
  • Account linked to user's profile
  • Starts at Tier 0 (Unverified)

Step 2: Set Transaction PIN

  • User creates a 4-digit PIN
  • PIN is required for all transactions
  • Securely hashed and stored
  • Adds security layer beyond login

Step 3: Verification (Optional Upgrades)

  • NIN Verification: Verifies national identity
  • Auto-Fetch: Pulls personal details from government database
  • Upgrade Approval: Increases transaction limits

Why Real Bank Accounts?

Unlike simple payment links, having a real bank account provides:

  • Regulatory Compliance: Meets CBN requirements for financial services
  • Trust: Users know their money is in a regulated institution
  • Flexibility: Receive transfers from any bank
  • Records: Complete transaction history for tax/giving receipts
  • Security: Bank-level security and insurance

7.3 Wallet Tier System

The tiered system follows CBN regulations for mobile money and ensures appropriate KYC (Know Your Customer) levels:

TierStatusDaily LimitSingle TransactionBalance LimitRequirements

2Standard₦500,000₦200,000₦500,000BVN + ID document

Benefits of Tiered System

  • Accessibility: Basic tier is easy to achieve for most users
  • Security: Higher limits require stronger verification
  • Compliance: Meets regulatory requirements
  • Flexibility: Users can upgrade as needed

7.4 Fund Wallet

Funding Process
